# UI and wording verification — 24 October 2026

Observed against the local Docker application at `http://localhost:3000`, with the existing warehouse. This is a dated functional and visual check, not accessibility certification, user research, an LLM accuracy benchmark, or evidence of uninterrupted scheduling.

## Changes verified

- CQ01 now asks which provinces have the most positive YoY months in the last twelve months. Its existing SQL still counts positive months, requires twelve paired observations, and returns up to ten provinces. It does not calculate a consecutive growth streak.
- All ten business questions show a data-derived summary before the visualization. Latest CQ01 identifies Pathum Thani at 12 of 12 paired months; CQ04 shows Prachin Buri / Phuket with a 10.55% GPP gap and 5.44-fold loan-size ratio.
- Province comparison places metrics in rows and selected provinces in columns. The GPP scatter defaults to the selected provinces. Switching to all provinces explicitly changes its scope; excluding Bangkok is available in that view.
- Bar comparisons show complete category names and exact values without hover, including two-province labels. Values and negative signs remain visible independently of the bar shape.
- Thai display dates use Buddhist years; annual source reference years remain explicitly labelled CE (`ค.ศ.`). SQL, bound parameters, and CSV data retain their original machine-readable values.
- Source coverage distinguishes eligible province-month rows from unavailable values, and retrieval time from reference period. The legacy ETL `started_at` column is labelled as result-recording time because it is populated when the result is inserted after processing.
- Technical router/planner identifiers appear in an expandable system detail, while the primary interface uses Thai operational labels. The observed assistant requests used the rules-based fallback, not a newly validated Gemini route.

## Local build limitations

A fresh API dependency installation failed because its package resolver could not obtain a matching `charset-normalizer` distribution. The API code was updated on the existing `bank-api` dependency image instead; no dependency upgrade was performed. The web image completed its normal production build.

The frontend tooling also reported an existing security advisory for the installed Next.js version. That dependency warning is separate from this UI change and remains unresolved here.

The C: drive fell below 1 GB free during the build. Only explicitly identified build-cache records created during this task were pruned (approximately 1.08 GB of Docker cache); older caches, user files, images, and database volumes were retained. The final Windows free-space reading was approximately 3.05 GB, still limited for another dependency rebuild. All five Bank services were restarted and inspected as running, with PostgreSQL healthy. This records their state at the end of this check, not future availability.
